Phishing Email Detection & Awareness Dashboard: Architecture

Static, defensive analysis. URLs are never visited, attachments are never opened, email bodies are never stored.

User (student / analyst)pastes email, uploads .eml/.txt, browses analytics
↓
Web DashboardHTML + vanilla JS + Chart.js (vendored) · strict CSP · data rendered as text only
↓ JSON over HTTP
Backend API (FastAPI)validation · size limits · rate limiting · optional auth (roles) · security logging
↓
Preprocessinglight cleaning (keeps caps, punctuation, URLs) · URL/domain/attachment extraction
↓
Sender Analyzerformat, domain, lookalike, display-name mismatch
Content Analyzerurgency, fear, financial, credential, reward, personal info
URL Analyzerraw IP, scheme, subdomains, shorteners, keywords (string-only)
Attachment Analyzerrisky types, double extensions (filename-only)
ML Model (optional)TF-IDF + indicators · Logistic Regression
↓
Risk Engine + Hybrid Blendrule score 0-100 (weights = assumptions) · 0.4 × rules + 0.6 × ML probability
↓
Classification · Explanation · RecommendationsLOW / MODERATE / SUSPICIOUS / HIGH RISK, with “Why?” list and actions
↓
SQLite (metadata only)analyses · indicators · url_analyses (defanged) · users · sessions
⇄
Dashboard analyticsKPI cards · 6 charts · history · awareness

Data flow: request → validate → preprocess → analyzers (+ optional ML) → score → classify → explain → store metadata → return JSON → render.
